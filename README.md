# 校园自习室预约系统

面向校园场景的自习室座位预约系统，Vue 3 + Vite 纯前端实现，使用浏览器 localStorage 持久化，不依赖任何后端服务。完整覆盖"查空闲座位 — 预约 — 签到 — 取消 — 爽约惩罚 — 管理端统计"闭环，并附带需求、设计、测试、论文全套毕业设计交付物。

## 功能概览

- **学生端**
  - 按自习室、日期、时段查询空闲座位，30 分钟粒度
  - 按"插座 / 靠窗 / 安静区"偏好智能推荐座位
  - 创建预约（7 天窗口、30-240 分钟、冲突检测）
  - 签到（开始前 15 分钟至开始后 15 分钟）、取消（开始前 30 分钟）
  - 信用分、等级、爽约记录、禁约剩余天数展示
- **管理端**
  - 预约量、签到率、爽约率、禁约人数等运营指标
  - 自习室使用率、时段热度、风险学生列表
  - 预约记录按状态/日期/关键词筛选，支持取消与标记爽约
  - 解除禁约、开关自习室、重置演示数据
- **系统能力**
  - localStorage 持久化，刷新不丢数据；脏数据自动回退种子数据
  - 角色路由守卫 + 动作级权限校验
  - 自动结算已完成预约、自动判定爽约并计分

## 技术栈

| 类别 | 选择 |
| --- | --- |
| 框架 | Vue 3.5（组合式 API） |
| 路由 | Vue Router 4（Hash 模式） |
| 构建 | Vite 6 |
| 测试 | Vitest 3 + @vitest/coverage-v8（v8 覆盖率） |
| 持久化 | localStorage（`srms:v1` / `srms:session:v1`） |
| 样式 | 原生 CSS（`src/styles.css`，无 UI 组件库） |

## 快速开始

环境要求：Node.js ≥ 18（本项目在 Node 24 下验证），npm ≥ 9。

```bash
# 1. 安装依赖
npm install

# 2. 启动开发服务器（默认 http://localhost:5173）
npm run dev

# 3. 生产构建
npm run build

# 4. 本地预览构建产物（默认 http://localhost:4173）
npm run preview
```

构建产物位于 `dist/`，为纯静态文件，可直接部署到任意静态服务器。`base: './'` 使资源使用相对路径，也支持放在子目录下访问。

## 测试

```bash
# 运行全部单元测试
npm test

# 生成覆盖率报告（终端 + coverage/index.html）
npm run test:coverage

# 监听模式
npm run test:watch
```

当前结果：

- 测试文件 6 个，用例 97 条，全部通过；
- 领域层覆盖率：语句 99.30%、分支 97.90%、函数 98.14%、行 99.30%；
- 覆盖率门禁：`vite.config.js` 中 `coverage.thresholds` 四项均为 80%，低于阈值时命令以非零码退出。

测试只覆盖 `src/domain/**/*.js`（纯函数，无 DOM、无 mock），时间通过入参注入，不依赖真实时钟。视图层通过 `docs/04-测试报告.md` 中的手工验收清单与截图覆盖。

## 核心业务规则

| 规则 | 取值 |
| --- | --- |
| 预约粒度 | 30 分钟，开始/结束必须对齐整点或半点 |
| 单次时长 | 30-240 分钟 |
| 可约窗口 | 当天至未来第 6 天（共 7 天） |
| 当天限制 | 已开始的时段不可预约 |
| 冲突语义 | 左闭右开，`09:00-10:00` 与 `10:00-11:00` 不冲突 |
| 签到窗口 | 开始前 15 分钟 ~ 开始后 15 分钟 |
| 取消截止 | 开始前 30 分钟（含） |
| 爽约判定 | 超过"开始 + 15 分钟"仍未签到 |
| 信用扣分 | 每次爽约 -10，下限 0 |
| 信用加分 | 每次签到 +2，上限 100 |
| 禁约触发 | 信用分 < 60 或累计爽约 ≥ 3 次 |
| 禁约时长 | 7 天；到期自动恢复，管理员可手动解除 |

## 数据持久化

| 键 | 内容 |
| --- | --- |
| `srms:v1` | `{ version, seedAt, users, rooms, seats, reservations }` |
| `srms:session:v1` | 当前登录用户 ID |

首次启动自动生成演示数据；若 `srms:v1` 的 JSON 损坏或版本不匹配，会自动重建，不会白屏。管理端"重置演示数据"可手动恢复初始状态。

## 已知限制

1. 纯前端无服务端并发控制，多个标签页同时预约同一座位可能互相覆盖；
2. 密码以明文保存在本地数据中，仅用于教学演示，不具备生产安全性；
3. 自动爽约扫描依赖页面打开（启动时执行一次，之后每分钟一次），页面关闭期间不会运行；
4. 时间以浏览器本地时区为准，未处理跨时区场景；
5. 视图层暂无组件级自动化测试，依赖手工验收与截图。
