| 项目 | 内容 |
| --- | --- |
| 文档编号 | SRMS-SRS-01 |
| 项目名称 | 校园自习室预约系统（Study Room Management System, SRMS） |
| 版本 | v1.0 |

## 1. 引言

### 1.1 编写目的

本文档定义校园自习室预约系统的用户角色、功能边界、业务规则、非功能指标与验收标准，作为概要设计、详细设计、编码实现与测试验收的共同依据。文档面向毕业设计评审教师、开发人员与测试人员。

### 1.2 项目背景

高校自习室长期存在三类问题：

1. **信息不对称**：学生到达自习室后才发现无座，往返成本高；
2. **占座不履约**：部分学生预约或占座后长时间不到场，座位资源闲置；
3. **管理缺少数据**：管理员无法掌握分时段使用率、爽约率与高风险用户。

本系统以"可查、可约、可核验、可追责、可统计"为目标，在纯浏览器环境中实现一套可演示、可测试、可部署的预约闭环。系统不依赖后端，数据保存在 localStorage，适合课程设计、毕业设计演示与原型验证。

### 1.3 术语定义

| 术语 | 定义 |
| --- | --- |
| 座位（Seat） | 自习室内可被单独预约的最小资源单位，具有编号、行列、靠窗、插座、区域属性 |
| 时段（Slot） | 以 30 分钟为最小粒度的连续时间区间，如 09:00-09:30 |
| 预约（Reservation） | 某学生占用某座位在某日某时段的记录 |
| 活跃预约 | 状态为 `reserved`（待签到）或 `checked_in`（已签到）的预约 |
| 签到窗口 | 预约开始前 15 分钟至开始后 15 分钟 |
| 爽约（No-show） | 超过签到窗口仍未签到的待签到预约 |
| 信用分（Credit Score） | 0-100 的履约评价，初始 100，爽约扣分，签到加分 |
| 禁约（Ban） | 信用分低于 60 或累计爽约 3 次时，7 天内禁止发起预约 |

## 2. 用户角色与权限

### 2.1 角色定义

| 角色 | 说明 | 典型用户 |
| --- | --- | --- |
| 学生 | 预约座位、签到、取消、查看个人信用 | 在校本科生、研究生 |
| 管理员 | 查看运营统计、管理预约记录、干预信用与自习室状态 | 教务处/图书馆工作人员 |

### 2.2 权限矩阵

| 功能 | 学生 | 管理员 | 未登录访客 |
| --- | --- | --- | --- |
| 登录 | 学号 + 密码 | 管理员账号 + 密码 | 可访问登录页 |
| 查空闲座位 | 可 | 不可（管理端无此入口） | 不可 |
| 创建预约 | 可 | 不可 | 不可 |
| 取消预约 | 仅本人预约 | 任意待签到预约 | 不可 |
| 签到 | 仅本人预约 | 不可代替签到 | 不可 |
| 查看个人预约与信用 | 仅本人 | 可查看全员预约记录 | 不可 |
| 标记爽约 | 不可 | 可 | 不可 |
| 解除禁约 | 不可 | 可 | 不可 |
| 开关自习室 | 不可 | 可 | 不可 |
| 运营统计 | 不可 | 可 | 不可 |
| 重置演示数据 | 不可 | 可 | 不可 |

权限由路由守卫与 store 动作双重校验：路由守卫拦截跨角色访问，store 动作校验操作者身份，避免仅靠前端隐藏按钮造成越权。

### 3.2 业务规则

| 规则编号 | 规则 |
| --- | --- |
| BR-01 | 最小预约粒度为 30 分钟，开始与结束时间均需对齐整点或半点 |
| BR-02 | 单次预约时长 30-240 分钟（0.5-4 小时） |
| BR-03 | 可预约当天至未来第 6 天，共 7 个自然日 |
| BR-04 | 当天已经开始的时段不可预约 |
| BR-05 | 时段采用左闭右开语义：09:00-10:00 与 10:00-11:00 不冲突 |
| BR-06 | 仅 `reserved` 与 `checked_in` 占用座位，`cancelled`、`no_show`、`completed` 不占用 |
| BR-07 | 签到窗口为开始前 15 分钟至开始后 15 分钟 |
| BR-08 | 取消截止为开始前 30 分钟，取消不扣信用分 |
| BR-09 | 爽约扣 10 分；签到加 2 分，上限 100 |
| BR-10 | 信用分 < 60 或累计爽约 ≥ 3 次触发 7 天禁约；重复触发不叠加延长正在生效的禁约 |
| BR-11 | 座位停用（`disabled`）或自习室关闭（`closed`）时不可预约 |
| BR-12 | 管理员取消预约不受"开始前 30 分钟"限制，但仍校验预约存在与权限 |

## 4. 用例描述

### UC-01 学生登录

- 参与者：学生
- 前置条件：系统已初始化演示数据，浏览器可访问页面
- 主流程：
  1. 打开系统，路由守卫将未登录用户引导至 `#/login`；
  2. 选择"学生登录"，输入学号 `2021001` 与密码 `123456`；
  3. 前端按 `account + role` 查找用户并比对密码；
  4. 登录成功后写入会话键 `srms:session:v1`，跳转 `#/student`。
- 异常流程：
  - 账号或角色不匹配：提示"账号不存在，或角色选择有误"；
  - 密码错误：提示"密码不正确"；
  - 账号或密码为空：提示"请输入账号和密码"。
- 后置条件：顶部导航显示学生姓名与学号，可访问学生端两个页面。

### UC-02 查询空闲座位

- 参与者：学生
- 前置条件：已登录学生账号
- 主流程：
  1. 选择自习室（默认"静思苑 A101"）；
  2. 选择日期（当天起 7 天）与开始/结束时间；
  3. 系统按 `splitRange` 生成 30 分钟切片，结合预约记录过滤冲突座位；
  4. 页面展示座位网格：空闲可点、占用置灰、推荐座位蓝框、已选座位绿框；
  5. 顶部展示"空闲 N / 总数 M 座"与本次时长。
- 异常流程：
  - 自习室被关闭：显示"该自习室当前暂停开放"并禁用时段与提交按钮；
  - 时段变更导致已选座位不可用：自动清空选择并提示重新选择。
- 后置条件：无数据写入。

### UC-03 预约座位

- 参与者：学生
- 前置条件：已登录，已选自习室、日期、时段与座位
- 主流程：
  1. 点击"确认预约"，调用 `validateReservation` 进行完整校验；
  2. 校验通过后生成 `id`（时间戳 + 随机串），状态为 `reserved`；
  3. 预约写入 `store.reservations`，深度侦听触发 localStorage 持久化；
  4. 页面提示"预约成功"并提供"查看我的预约"入口。
- 异常流程：
  - 未选座位：提示"请先在座位图中选择一个空闲座位"；
  - 座位被抢占：提示"该座位在所选时段已被预约"；
  - 同一时段已有预约：提示"你在所选时段已有其他预约"；
  - 处于禁约期：提示"你当前处于爽约禁约期，暂不能预约"。
- 后置条件：该座位在所选时段从空闲列表移除；同一学生该时段不可再预约其他座位。

### UC-04 签到

- 参与者：学生
- 前置条件：存在当日 `reserved` 预约，且当前时间处于签到窗口
- 主流程：
  1. 进入"我的预约"，在"进行中"列表点击"签到"；
  2. `canCheckIn` 校验状态、日期与时间窗口；
  3. 状态改为 `checked_in`，写入 `checkedInAt`；
  4. 调用 `applyCheckIn`，信用分 +2（上限 100）。
- 异常流程：
  - 不在窗口内：提示"签到窗口为开始前 15 分钟至开始后 15 分钟"；
  - 非本人预约：提示"无权操作该预约"；
  - 预约不存在：提示"预约记录不存在"。
- 后置条件：该预约在到达结束时间后被自动结算为 `completed`。

### UC-05 取消预约

- 参与者：学生、管理员
- 前置条件：预约状态为 `reserved`，且距离开始时间不少于 30 分钟（管理员不受此限）
- 主流程：
  1. 点击"取消预约"并二次确认；
  2. 校验操作者身份（学生仅本人，管理员任意）；
  3. 状态改为 `cancelled`，写入 `cancelledAt`；
  4. 座位立即回到空闲池，信用分不变。
- 异常流程：
  - 已进入 30 分钟截止区：提示"仅可在开始前 30 分钟取消待签到预约"；
  - 状态非待签到：按钮禁用；
  - 越权操作：提示"无权操作该预约"。
- 后置条件：该时段座位可被其他学生预约。

### UC-06 爽约判定与信用惩罚

- 参与者：系统（定时/手动触发）、学生、管理员
- 前置条件：存在超过"开始时间 + 15 分钟"仍未签到的 `reserved` 预约
- 主流程：
  1. 应用启动、每分钟定时器、学生端"立即检测"或管理端"检测爽约"触发 `sweepNoShows`；
  2. `getNoShowCandidates` 筛选候选记录；
  3. 逐条置为 `no_show`，写入 `noShowAt`；
  4. 调用 `applyNoShow`：信用分 -10（下限 0），爽约次数 +1；
  5. 若信用分 < 60 或爽约次数 ≥ 3，写入 7 天后的 `bannedUntil` 与 `banReason`。
- 异常流程：
  - 已签到/已取消记录不参与判定；
  - 已有未到期禁约不重复延长；
  - 管理员可手工标记单条爽约，非 `reserved` 状态拒绝。
- 后置条件：学生进入禁约期，学生端预约入口提示受限；管理端"爽约与信用管理"出现该生记录。

### UC-07 管理端运营统计

- 参与者：管理员
- 前置条件：已登录管理员账号
- 主流程：
  1. 进入 `#/admin`，默认展示"明天"（示例数据日期）；
  2. `buildOverview` 统计预约总量、当日预约、签到率、爽约率、禁约人数、风险人数；
  3. `occupancyByRoom` 按"已预约分钟 / 座位数 × 开放分钟"计算各室使用率；
  4. `hourlyHeatmap` 聚合 08:00-21:00 各整点有效预约数；
  5. 展示最近 6 条预约与风险学生列表。
- 异常流程：
  - 有效预约为 0：签到率、爽约率返回 0，不出现 `NaN`；
  - 容量为 0（开放时间为空）：使用率返回 0；
  - 使用率超过 100%：展示层截断为 100%。
- 后置条件：无数据写入。

### UC-08 管理员干预

- 参与者：管理员
- 前置条件：已登录管理员账号
- 主流程：
  1. 解除禁约：`liftBan` 清空 `bannedUntil` 与 `banReason`，保留信用分与爽约次数；
  2. 关闭/开放自习室：`toggleRoomStatus` 切换 `open/closed`；
  3. 预约干预：在 `#/admin/reservations` 取消待签到预约或标记爽约；
  4. 重置演示数据：`resetDemoData` 恢复初始数据并退出登录。
- 异常流程：
  - 用户/自习室/预约不存在：返回"不存在"错误，不修改数据；
  - 重置需二次确认，确认后整页刷新。
- 后置条件：学生端下一次渲染立即反映变更。

### 6.2 初始数据

## 7. 约束与假设

1. 系统为纯前端演示，无真实身份认证、无服务端并发控制；多标签页同时写入可能互相覆盖，属于已知约束；
2. 密码以明文存储于本地数据，仅用于演示，不作为生产安全方案；
3. 时间以浏览器本地时区为准，不处理跨时区场景；
4. 不接入短信、二维码、门禁等硬件签到方式；
5. 统计口径以本地记录为准，不支持跨设备汇总。

## 8. 范围外

- 真实支付、押金、违约金；
- 座位扫码签到、人脸识别；
- 与教务系统/一卡通系统对接；
- 多校区、多租户与权限分级；
- 服务端数据库与实时推送。

## 9. 验收标准

1. 第 3.1 节全部 P0 功能可演示，P1 功能可用；
